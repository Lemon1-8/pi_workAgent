# 电商 Work Agent

基于 Pi SDK 的本机网页原型。面向电商团队的批量表格工作，第一条流程是订单合并。已实现批量文件上传、分片续传与内容核对、持久任务记录、独立 Python 执行任务、结果下载和受控 Pi 工具接入。

第一期需求是约 50 人、200 个店铺、单批上千份 XLSX，每份约 5MB。现有 Python 程序一批约 40 分钟；这些规模与耗时是后续真实基准测试的条件。

## 本机启动

需要 Node.js 22.19 或更新版本、Python 3.10 或更新版本。

```powershell
npm install --ignore-scripts
python -m pip install -r requirements.txt
Copy-Item .env.example .env
npm start
```

打开 [本机工作台](http://127.0.0.1:4317)。已有 `.env` 时保留自己的配置。运行数据保存在项目 `.data/batches/`，源码与配置示例不包含上传的业务数据。

## 当前可以验证的流程

新建任务，选择文件夹，确认文件清单并上传。清单可按文件、店铺及状态筛选，误选项可以移除；已登记文件可填写原因排除，也可以明确替换为同路径、同名的新版本。选择文件时忽略 Excel 的 `~$` 临时文件。服务端按标识保存文件，每个文件完成后对比 SHA-256。上传可暂停，重新选择同一文件夹后继续；变化的文件需先点“确认替换”。每次最多同时传 3 个文件，每片 4MB。

配置示例默认连接 `examples/merge_adapter.py`。上传后点击“检查输入”，后台逐文件检查所有所选工作表和数据行，展示来源字段、有限样例、异常位置和重复内容提示。未通过检查不能启动合并。可选择工作表、设置统一结果字段，并对不同来源的字段组合明确映射或忽略列，再点击“确认规则并检查”。原始字符串与前导零保持文本，并附加来源文件、工作表和行号。结果超过 Excel 单表行数限制时拆成多份文件。

检查流程要求数据表的首个非空行为唯一、非空的文字表头，最多 512 列。未知字段组合需明确映射，公式单元格需提供值数据。规则可保存为命名模板；同名保存创建新版本，新任务可选择指定版本复用。模板以快照保存在 `.data/batches/templates.json`，不随其他任务的修改改变。订单业务粒度、去重、退款和费用处理仍需由现有脚本或经业务样本确认的规则实现；聊天不会自动改写页面配置。

检查成功的文件保存为按内容、来源路径、字段规则和处理版本区分的检查点。异常会集中列出文件、工作表和行号；修正或替换后点击“只重试异常文件”，未变化的成功输入复用检查点。输入或规则一旦改变，旧检查通过状态立即失效。排除项及其原因进入报告；重复内容仅提示，不自动业务去重。检查点跨重启保留，内容校验失败时重建。局部重试复用逐文件解析，最终成果会重新完整汇总、导出并验收。

后台同时执行一个合并批次，其他批次排队。上传、检查、执行和成果验收状态来自实际事件。取消停止执行和验收进程；失败和中断可重试，每次写入独立输出目录。重启后，运行中的任务和检查标记为中断，上传分片与检查点保留。完成前逐份打开并遍历结果工作簿，核对总记录数；默认流程还核对结果字段。损坏文件或数量不一致会判为失败，不能作为成功成果交付。成果支持选择工作表、每页 25 条预览、下载 XLSX 和 `summary.json`；检查报告也可下载。

## 配置 Pi 模型

在本机 `.env` 设置 `PI_PROVIDER`、`PI_MODEL` 与 `PI_API_KEY`，供应商与模型需对应 Pi 1.2.0 模型目录，然后重启服务。密钥留在服务端，网页只获取配置是否齐备。

配置后，任务对话可让 Pi 查询当前批次、发起订单合并和查询有限结果报告。仅开放这三个工具；Agent 不获取完整原表，也不提供任意 shell 或本地文件读取工具。没有模型配置时，上传和人工启动流程仍可使用。

每批一个 Pi 会话。网页历史持久保存；后台重启后，当前原型的模型上下文重新开始。真实模型联调需要用户自己的模型配置；自动化测试使用 Pi 自带离线 Faux 流。

## 接入现有 Python 脚本

将 `.env` 的 `MERGE_SCRIPT` 替换为适配器文件路径。可在薄适配器中调用现有脚本的函数或命令行入口，保留已经确认的业务规则。服务按以下方式调用，无 shell 拼接：

```text
python <adapter.py> --manifest <manifest.json> --output-dir <output-directory>
```

清单结构：

```json
{
  "batchId": "任务标识",
  "files": [{
    "id": "文件标识",
    "name": "订单.xlsx",
    "relativePath": "店铺/订单.xlsx",
    "path": "服务端输入文件完整路径",
    "size": 5242880,
    "sha256": "文件内容校验值"
  }]
}
```

适配器在指定输出目录生成 XLSX。退出码为 0、至少有一份 XLSX 且全部工作簿通过可读性验收后才能成为完成状态；如 `summary.json` 提供整数 `recordCount`，还会核对实际记录数。可附带 CSV 异常明细和不超过 64KB 的 `summary.json`。清单额外提供 `excluded` 和 `workflow`（规则、输入版本及检查点目录）；现有适配器可继续只读取 `files`。默认示例接入完整模板和检查点流程，自定义脚本需主动适配该协议，页面会明确显示支持范围。

向 stdout 输出可选 JSONL 进度，每行一个对象并及时 flush：

```json
{"type":"progress","phase":"parsing","current":5,"total":1000,"message":"已解析 5 份文件"}
```

stderr 用于失败诊断，应用只保留末尾有限内容。适配器与任务服务的接口不包含具体平台映射规则；原脚本目前不在本机，待取得后检查入口、依赖、进度与恢复能力。

## 验证

```powershell
npm run check
npm test
python -m unittest discover -s examples -p "test_*.py"
```

测试覆盖上传状态和校验、清单纠错与修改锁、任务恢复、调度失败与取消、重试不重复排队、Pi 工具边界、字段映射与工作表选择、模板版本持久化、多个异常汇总、检查点复用及失效、成果字段和记录数验收、伪 XLSX 拒绝及分页预览。工作流集成测试通过 HTTP 上传真实工作簿、替换异常输入、复用检查点、合并、验收和下载；传输契约与调度单元测试另用受控字节夹具。

## 团队部署与后续流程

当前只绑定 `127.0.0.1`，用于本机开发，尚未接入成员登录与任务访问控制。50 人内部部署需要服务器、成员身份、任务归属、存储与备份，以及真实峰值负载验收。千文件约 5GB 的完整批次与比现有 40 分钟更快的性能目标尚需实测。

订单合并验证后，增加 ERP 与平台对账、销售和库存分析工具，复用任务、文件与来源追溯能力。需求、竞品资料和规格见 [调研与需求](docs/work-agent-discovery.md) 与 [第一期规格](docs/order-merge-mvp.md)。
